# 0003：人工编号一次播种与 Hash 扩散

## 状态

已接受；本轮明确人工 DOWN 的来源和同号优先播种规则，不扩大未决聚合边界。

## 背景

**历史事实**：UP/DOWN 仅摄入人工转发，不摄入 Writer 自己生成的普通消息。人工操作持久化当时的种子记录集合，UP 重建可复用这些显式关系。

**推断动机**：编号适合人工指定“这批历史记录”，但如果每次 Hash 扩散都重新查编号，会把以后出现的同号记录意外纳入永久规则。

## 决策

1. 人工向 UP/DOWN 转发单条或相册，先解析编号，查找当时成功归档历史中的同号记录作为种子，再加入本次输入。
2. **本轮澄清**：人工 DOWN 允许任意来源的带编号转发；即使媒体不同，也先命中成功历史同号记录，不要求来源必须是某个归档频道。
3. 从种子沿全部媒体 Hash 递归扩散，不在递归过程中再次搜索编号。未来 FROM 仍只按成功历史 Hash 分类，不按编号升类。
4. UP 保存人工种子关系供后续连通集合重建；已有 DOWN Hash 优先，人工 UP 不能覆盖。DOWN 使用 Hash 唯一插入与队列追溯，不聚合，不沿人工编号关系继续扩大。
5. 人工 DOWN 原消息保留，其他被选中的记录独立归档；只沿 Hash 命中 UP 一支时，剩余 UP 安全重建。

## 替代方案

只按 Hash 会遗漏人工明确指定的同号不同媒体历史；将编号变成永久图边的实时查找规则则会污染未来输入。限定 DOWN 必须来自内部频道不符合本轮确认的人工入口。

## 后果与局限

操作结果依赖当时成功历史，不能用未来同号记录倒推旧种子。UP 聚合整体转 DOWN 仍未确认；当前多编号输入进入 MAN，不因本 ADR 宣称聚合已整体迁移。
