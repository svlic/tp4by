# 0002：record 身份、业务编号与媒体 Hash 分离

## 状态

已接受；图片判等规则经本轮明确，纯色排除延期。

## 背景

**历史事实**：一次输入有事件唯一键和独立 record ID，业务编号不是主键；不同输入可同号，同一媒体也可存在于多个记录。媒体原件另以内容摘要定位存储。

**推断动机**：如果把编号、输入身份或媒体内容混为一谈，就会丢失独立归档历史，或让未来同号输入被无条件升类。

## 决策

- record 表示一次输入，事件唯一键用于接收去重，业务编号用于展示与人工操作的一次播种。三者不相互替代。
- 从合并文本中解析唯一的不同 6/7 位数字编号；重复同一编号有效，无编号或多个不同编号进入 MAN。
- 图片，包括可解码的 document 图片及 MIME 标注错误的图片，使用 **64 位 pHash 精确相等**；视频使用文件内容 SHA-256。Hash 键包含媒体类型和算法。
- 原件存储使用的 SHA-256 不取代图片业务 pHash。同一 pHash 可保留多份不同原件，以便展示时选择可读副本。
- **本轮澄清**：不增加图片距离阈值，也不追加其他二次校验。纯色图片排除明确延期，不以隐式特例改变现行判等。

## 替代方案

业务编号唯一约束会拒绝合法同号输入；仅使用文件 SHA-256 会改变图片判等业务；pHash 阈值或二次校验会引入本轮未授权的分类规则，均不采用。

## 后果与局限

pHash 相同不等于文件字节相同，可能出现碰撞，纯色等场景的风险仍存在。原件保留不能自动消除业务 Hash 碰撞。编号解析规则不承担更复杂的正文语义识别。
